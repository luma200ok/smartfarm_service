### 6. 회고 — 픽스가 회귀를 부른 패턴 (2026-08-24, #116 사이클)
PR #117에서 리뷰 P1 2건을 고치는 픽스가 **새 회귀 2건을 유발**했고, 재검토 루프가 그걸 잡아 같은 사이클에서 처리했다.
- **회귀-A**: P1 픽스를 "리뷰어가 짚은 그 줄만 try/catch로 감싸라"고 지시 → 같은 루프의 **형제 호출부**(`autoResolveIfOpen`)가 누락. 게다가 별도로 지시한 P2 픽스가 그 미처리 호출부의 호출 빈도를 올려 발생 확률이 오히려 상승.
- **회귀-B**: `findEnabledWithWebhookConfigured()` → `findEnabled()` 교체를 지시했는데, 구 쿼리의 Farm 서브쿼리가 **웹훅 조건 외에 soft delete 필터도 겸하고 있었다**(javadoc에 명시돼 있었음). 메타가 그 파일을 직접 읽지 않고 리뷰 보고서만 보고 지시.
- **근인**: 리뷰 보고서를 1차 소스로 취급(R1 stale 단정 패턴). 구현 서브는 정의상 지시 범위만 수행하므로 **범위를 넓게 잡을 책임은 메타에 있는데** 그걸 리뷰어에게 위임했다.
- **적용 중인 대책**: ①픽스 지시 **전**에 메타가 해당 파일을 직접 읽어 형제 호출부·그 코드가 겸하는 다른 불변식(주석 포함) 확인 ②조건·쿼리를 **제거**하는 픽스는 "이 조건이 무엇을 겸하는가" 필수 체크 ③여러 픽스 동시 지시 시 상호작용(호출 빈도·대상 범위 변화) 검토 ④픽스 **후** 메타가 직접 diff·grep으로 검증한 뒤 재검토 의뢰
- **효과(2026-08-25 확인)**: #118·#122 두 사이클에서 **픽스 유발 회귀 0건**. 구현자가 스스로 "겸하던 불변식"을 찾아내는 사례가 나왔다(`resetFarm`의 `removeIf`가 쿨다운 보존과 맵 정리를 겸하던 것 → `forgetRule` 분리 / `UserService`의 OWNER 검사가 A006과 "탈퇴로 마지막 관리자 삭제" 봉쇄를 겸하던 것 → 완화하지 않고 1:1 치환).

### 6-2. 뮤테이션 검증을 사이클에 넣은 뒤 드러난 것 (2026-08-25)
"테스트가 통과한다"와 "테스트가 회귀를 잡는다"는 다르다. 픽스마다 **의도적으로 코드를 되돌려 테스트가 빨개지는지** 확인하기 시작하자 아래가 드러났다:
- **naive 동시성 테스트가 락 없이도 통과**(#118) — check-then-act 창이 짧아 스레드 시작 지터로는 인터리브가 안 된다. 결정론적 블로킹 관측 방식으로 교체
- **멘션 억제 테스트가 `toString()`을 보고 있었다**(#118) — `@JsonProperty("allowed_mentions")`를 지워도 초록. 실제 JSON 직렬화 단언으로 교체(보안 통제의 회귀 감지 구멍이었다)
- **V21 이관 테스트가 flush 순서 때문에 이관을 `VIEWER`로 바꿔도 초록**(#122) — 기능 회귀를 못 잡는 상태
- **대기 취소 테스트가 ADMIN 토큰을 빌려 `memberId`를 얻고 있었다**(#122) — "BE엔 탈출구가 있는데 FE에선 도달 불가"인 상태를 덮고 있었고, 이걸 고치자 `GET /api/farms`에 `memberId`가 필요함이 드러났다
→ **테스트가 실제 사용자가 손에 넣을 수 있는 값·경로만 쓰는지**가 핵심 판별 기준이다.
